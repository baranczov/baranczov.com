# baranczov.com

Персональное портфолио Данила Баранцова по описанию от 23 октября 2026 года. Работающий Python-проект: сайт, управление контентом, миграции, импорт изображений и конфигурация для размещения на сервере.

## Стек и архитектура

- **Python 3.12 + Django 5.2 LTS.** Django отдаёт готовый HTML и предоставляет админку, ORM, миграции, авторизацию и валидацию форм. Отдельный API и SPA этому портфолио не нужны.
- **Django Templates + CSS + JavaScript ES modules.** CSS отвечает за оформление и адаптивность. Модули `carousel.js`, `marquee.js`, `app.js` — за движение и настройки интерфейса. Node.js и сборщик для запуска не требуются.
- **SQLite локально, PostgreSQL при размещении.** База переключается через `DATABASE_URL`.
- **Gunicorn + WhiteNoise + Caddy.** Gunicorn обслуживает Django, WhiteNoise — версионированную статику, Caddy — HTTPS и загруженные изображения. Docker Compose содержит PostgreSQL и постоянные тома для БД и медиа.
- Шрифты Montserrat и Manrope, включая кириллицу, хранятся локально в WOFF2. Посетитель не обращается к Google Fonts.

Версии зависимостей зафиксированы в `uv.lock`; `requirements.txt` содержит те же версии и хеши для Docker. Выбор LTS и production-настройки опираются на [поддерживаемые версии Django](https://www.djangoproject.com/download/) и [deployment checklist](https://docs.djangoproject.com/en/5.2/howto/deployment/checklist/).

```text
Browser → Caddy (HTTPS) → Gunicorn → Django views → templates
                 │                       │
                 └─ /media/              └─ ORM → PostgreSQL
                                         └─ /admin/ → content management
```

```text
config/             настройки, маршруты и WSGI
portfolio/          модели, views, админка, переводы интерфейса, тесты
  management/       seed_portfolio и import_design
  migrations/       схема базы данных
templates/          серверные шаблоны страницы и sitemap
static/             CSS, JS, локальные шрифты и favicon
user_design/        исходные изображения и инструкция по экспорту
deploy/             конфигурация Caddy и скрипт резервного копирования
scripts/dev.sh      локальный запуск одной командой
```

## Быстрый запуск

Установите Python 3.12+ и [uv](https://docs.astral.sh/uv/getting-started/installation/), затем в каталоге проекта:

```sh
./scripts/dev.sh
```

Скрипт создаёт `.env`, если его ещё нет, устанавливает зафиксированные зависимости, выполняет миграции, добавляет базовый контент и импортирует изображения из `user_design/`. Повторный запуск сохраняет внесённый контент. Сервер слушает только `127.0.0.1:8000`.

- Сайт: <http://127.0.0.1:8000/ru/>
- Английская версия: <http://127.0.0.1:8000/en/>
- Админка: <http://127.0.0.1:8000/admin/>

Создать администратора, задав собственный пароль:

```sh
uv run python manage.py createsuperuser
```

Для повторного запуска уже настроенного проекта достаточно `uv run python manage.py runserver 127.0.0.1:8000`.

## Контент

В админке доступны профиль, рабочий опыт, проекты, шесть категорий технологий и контакты. Тексты RU/EN заполняются раздельно. Порядок и публикацию карточек можно менять прямо в списке. Неопубликованные записи на сайте не отображаются.

В профиле есть отдельные поля «Резюме PDF RU» и «Резюме PDF EN». Сота «Резюме» на `/ru/` открывает русский файл, а «CV» на `/en/` — английский. Если файл для выбранного языка не загружен, соответствующая сота неактивна.

Под именем отображается роль ML Engineer / Data Scientist обычным начертанием. Биография начинается с ML, NLP и production-пайплайнов; далее сохранён текст об образовании, опыте, достижениях и личных качествах. Кнопка под фотографией открывает резюме на выбранном языке в новой вкладке. Миграция `0020` обновляет задачи компаний по резюме от 26 октября 2026 года, сохраняя даты, изображения и настройки публикации; `0021` возвращает прежнюю биографию с новым вводным предложением. Проверка миграции Т-Банка включена в описание миграции ML-инфраструктуры, чтобы на карточке осталось три задачи.

Начальные данные включают утверждённые сведения: профиль, три места работы (Т-Банк, IT_ONE и ВкусВилл), должности, даты и по три задачи с подробными описаниями на русском и английском, шесть категорий технологий и контакты. Миграция `0007` заполняет опыт в существующей базе; повторный `seed_portfolio` сохраняет последующие авторские правки и удаление задач. Утверждённые ссылки GitHub, Kaggle, Gmail, Telegram и Instagram показаны в сотах. LinkedIn остаётся неактивным до заполнения ссылки; сота «Резюме» ведёт на PDF из профиля, если он загружен. Добавлены шесть утверждённых проектов с описаниями и ссылками GitHub; у двух соревнований есть ссылки Kaggle. Миграция `0010` заполняет проекты в существующей базе.

В разделе опыта три карточки без повторов: берутся первые три опубликованные записи по порядку в админке. Лицевые стороны показывают предоставленные обложки Т-Банка, IT_ONE и ВкусВилла. На оборотах показаны должности, три кликабельных названия задач и периоды работы. Названия, описания и переводы задач редактируются внутри места работы в админке; задачу можно скрыть флагом публикации. При добавлении записей в админке обложки сопоставляются по названию компании; загруженная через админку картинка имеет приоритет. Скрытая запись не возвращается в виде обложки. Проекты вращаются кольцом, которое включает все опубликованные проекты. Если карточек от двух до пяти, полная последовательность повторяется до заполнения минимум шести позиций; например, три заглушки дают A–B–C–A–B–C. Большие коллекции показываются без повторов, радиус кольца растёт с количеством карточек. Счётчик показывает количество уникальных проектов. Заглушки и повторы не создают записей в базе.

uv run python manage.py import_design

## Типографика

Общая шкала задана переменными в `static/css/style.css`: разделы — 100 px, имя — 90 px, подзаголовки — 40 px, обычный текст — 30 px, маленькие подписи — 20 px. Эти размеры используются при ширине макета 1655 px и выше; на планшетах и телефонах шкала адаптивно уменьшается. Имя и фамилия сохраняют одну строку и на мобильном экране.

## Поведение интерфейса

- Верхняя строка уходит при прокрутке, синяя навигация остаётся сверху. Активный раздел обновляется при прокрутке. На узком экране меню прокручивается горизонтально.
- `/ru/` и `/en/` — самостоятельные серверные страницы; выбор языка сохраняется cookie. Смена языка сохраняет якорь текущего раздела.
- Светлая тема включена по умолчанию, выбранная тема сохраняется в `localStorage`. Тёмная палитра и мобильная компоновка — реализационные решения, так как в PDF отдельные макеты отсутствуют.
- Проекты повторяют движение из видео: карточки вращаются по объёмному кольцу, левая выходит вперёд, задние затемняются и имеют противоположный наклон. Поворот занимает 650 мс, остановка между поворотами — 1,2 с. Угол непрерывен, резкого сброса на границе круга нет. Рабочий опыт использует прежнюю анимацию проектов: центральная карточка и две боковые с поворотом и уменьшением, пауза 3,6 с и переход 700 мс. Режим задаётся атрибутом `data-motion` отдельно от типа контента.
- Наведение и фокус останавливают автопрокрутку. Открытая обратная сторона удерживает паузу после ухода курсора. Боковая карточка переходит в центр; центральная карточка опыта или проекта переворачивается. Явные кнопки, стрелки клавиатуры, колёсико и горизонтальное перетаскивание управляют каруселью. `Escape` сначала закрывает описание задачи, затем обратную сторону.
- Выбор задачи плавно сдвигает карточки опыта влево и открывает справа плашку с полным описанием. Плашка растёт по высоте текста без внутренней прокрутки; раздел расширяется вслед за ней. На экранах до 1050 px описание появляется под карточкой. Крестик и `Escape` возвращают фокус к задаче; смена компании и переворот закрывают описание. В закрытом состоянии плашка скрыта и исключена из навигации. Без JS задачи доступны через обычные раскрывающиеся блоки.
- На лицевой стороне проекта показан заголовок, на обороте — описание и нижняя строка ссылок GitHub/Kaggle. Номеров на карточках нет. При перевороте высота карточки и секции подстраивается под полный текст с сохранением размера шрифта; при закрытии возвращается квадратная обложка. Открытый оборот удерживает автопрокрутку. Вертикальная прокрутка над описанием прокручивает страницу, ссылки открываются отдельно. Кнопка ↶ или `Escape` возвращает лицевую сторону. Тексты, переводы и ссылки редактируются в разделе проектов админки.
- Над карточками техстека расположена статичная полоса из 13 SVG-иконок. Фоновый узор повторяется по всей ширине без анимации и пустых участков при уменьшении масштаба. Карточки техстека движутся непрерывно со скоростью 25 px/с, останавливается при наведении и фокусе, поддерживает колёсико, стрелки и перетаскивание. Карточки стека показывают технологии через запятую и автоматически выравниваются по самой высокой; номера, подсказка и кнопка паузы убраны по макету. Раздел контактов содержит синий фон с 13 движущимися строками «МОИ КОНТАКТЫ» размером 40 px на макетной ширине. Поверх фона расположены семь сот: четыре сверху и три ниже со сдвигом. На телефоне они перестраиваются в ряды 2–3–2. Предоставленные SVG-логотипы сохранены в `static/images/contacts/`; кнопки паузы в разделе нет.
- В рабочем опыте и проектах стрелки и счётчик выровнены вправо; подсказки и кнопки паузы убраны. `prefers-reduced-motion` отключает автоматическое движение, ручная навигация остаётся доступной. В режиме без JS контент доступен с обычной горизонтальной прокруткой.

Тайминги выбраны как стартовые значения из предложений PDF. Дополнительное морфирование фотографии и появление секций намеренно не добавлены: в документе они не утверждены. При необходимости значения меняются в JS-модулях и CSS.

### Производительность и проверки

На экранах шире 760 px интерфейс по умолчанию отображается в масштабе 90% через CSS `zoom`. На телефонах и при печати масштаб остаётся 100%. Масштаб браузера пользователь может менять самостоятельно. Геометрия каруселей и ленты техстека рассчитывается в координатах вёрстки, перетаскивание учитывает масштаб интерфейса.

Карусели используют `requestAnimationFrame` только во время движения, а между переходами — один таймер. При паузе, уходе раздела за экран или скрытии вкладки циклы останавливаются. Строки фона контактов также анимируются только в видимом разделе. Геометрия карточек пересчитывается при изменении размеров, состояние клавиатурного фокуса — при смене активной карточки или перевороте. Цвет проекта хранится в его записи и не зависит от порядка карточек.

Публичная страница выполняет 6 запросов к базе без дополнительных запросов для каждой карточки. Для небольшого портфолио отдельный сервис кэширования не требуется. Изображения сжимаются заранее, а не во время HTTP-запросов. PNG-обложки и фото сохраняются как WebP без потери качества; встроенные PNG в статических SVG перекодируются так же, с сохранением разрешения. Исходники в `user_design/` и прежние файлы в `media/` остаются на месте. После загрузки новых изображений можно выполнить:

```sh
uv run python manage.py optimize_images             # оценка без записи
uv run python manage.py optimize_images --apply     # сохранить оптимизированные копии
uv run python manage.py collectstatic --noinput
```

Локальные CSS и JavaScript, включая импортируемые модули, получают версии по содержимому; в production используются имена из manifest. Проверки:

```sh
uv run python manage.py test
uv run python manage.py makemigrations --check --dry-run
node --test tests/*.test.mjs
```

Node.js нужен только для тестов JavaScript; сайт работает без Node.js на сервере. Нагрузочные характеристики боевого хостинга необходимо измерять после развёртывания.

## Размещение на сервере

### Действующий сайт

Сайт опубликован 24 октября 2026 года: <https://baranczov.com/ru/> и <https://baranczov.com/en/>. VPS Vultr — `108.61.211.219`, каталог приложения — `/opt/baranczov`. DNS обслуживают `ns1.reg.ru` и `ns2.reg.ru`; A-записи `@` и `www` указывают на IP сервера. Caddy автоматически получает и продлевает сертификаты HTTPS; `www` перенаправляется на основной домен с сохранением пути.

Перенесены все 32 записи контента и восемь файлов из локальной базы. Содержимое записей и SHA-256 файлов сверены после переноса. Администратор пока не создан; для его создания можно выполнить на сервере `docker compose --env-file .env.production exec web python manage.py createsuperuser` из каталога приложения.

Подключение с этого Mac:

```sh
ssh -i ~/.ssh/baranczov_vultr -o IdentitiesOnly=yes root@108.61.211.219
cd /opt/baranczov
docker compose --env-file .env.production ps
docker compose --env-file .env.production logs --tail=100 web proxy
```

SSH принимает ключи; вход по паролю отключён. UFW разрешает входящие TCP 22, 80 и 443. PostgreSQL и Gunicorn доступны только внутри сети Compose. Секреты находятся в `.env.production` на сервере с правами `600`. Логи каждого контейнера ограничены тремя файлами по 10 МБ. После запуска три контейнера суммарно использовали около 150 МБ RAM; это разовый замер при небольшой нагрузке, а не нагрузочный тест.

На VPS фактически установлена **Ubuntu 26.10**, хотя при оформлении планировалась LTS. По [срокам поддержки Ubuntu](https://ubuntu.com/about/release-cycle) её поддержка заканчивается в июле 2027 года. До этого срока нужно перенести сервис на поддерживаемую LTS-систему.

### Обновление действующего сайта

Перед заменой исходников создайте копию командой `bash /opt/baranczov/deploy/backup.sh`. Перенесите изменённые исходники в `/opt/baranczov`, сохранив `.env.production`, затем выполните из этого каталога:

```sh
docker compose --env-file .env.production build web
docker compose --env-file .env.production run --rm web python manage.py migrate --noinput
docker compose --env-file .env.production run --rm web python manage.py check --deploy --fail-level WARNING
docker compose --env-file .env.production up -d
curl --fail --silent --show-error https://baranczov.com/health/
```

При обновлении не нужно повторно импортировать начальный контент. Не используйте `down -v`: эта команда удалит тома с базой и загруженными файлами. `collectstatic` выполняется при сборке образа. При изменении `deploy/Caddyfile` проверьте и перечитайте конфигурацию командами `docker compose --env-file .env.production exec proxy caddy validate --config /etc/caddy/Caddyfile` и `docker compose --env-file .env.production exec proxy caddy reload --config /etc/caddy/Caddyfile`.

### Резервные копии

Скрипт `deploy/backup.sh` сохраняет дамп PostgreSQL в custom-формате, архив медиа, `.env.production`, Compose и Caddyfile в `/opt/baranczov-backups/backup-<UTC>`. Права закрывают доступ другим пользователям; `SHA256SUMS` позволяет проверить целостность, а `COMPLETE` отмечает завершённую копию. Завершённые копии старше 14 дней удаляются автоматически.

На VPS включён systemd-таймер `baranczov-backup.timer`: ежедневно в 03:20 UTC с дополнительной случайной задержкой до 15 минут. Проверка и ручной запуск:

```sh
systemctl list-timers baranczov-backup.timer
systemctl start baranczov-backup.service
journalctl -u baranczov-backup.service -n 20 --no-pager
```

Первая копия `backup-20261024T163024Z` проверена: контрольные суммы совпадают, `pg_restore --list` и `gzip -t` читают архивы без ошибок. Она также сохранена на Mac в `tmp/backups/backup-20261024T163024Z/` этого проекта. **Автоматические копии пока хранятся на том же VPS**; периодически скачивайте свежую копию на другой носитель. В архиве есть секреты, его нельзя публиковать или добавлять в Git.

Для восстановления разверните исходники нужной версии и Docker Compose на новом сервере, восстановите `.env.production` с правами `600`, запустите только БД, затем загрузите `database.dump` через `pg_restore --no-owner --no-privileges --exit-on-error -U portfolio -d portfolio` внутри контейнера `db`. База должна быть пустой. Распакуйте `media.tar.gz` в том `media_data` и назначьте владельца файлов `10001:10001`. После этого запустите `web` и `proxy`, проверьте `/health/`, страницы и файлы и только затем переключайте DNS. Контрольные суммы проверяйте до восстановления командой `sha256sum -c SHA256SUMS` в каталоге копии.

### Новая установка с начальным контентом

Следующие шаги предназначены для отдельной новой установки, а не для обновления действующего сайта.

1. Скопируйте `.env.production.example` в `.env.production` и заполните домен, `SITE_URL`, `DJANGO_ALLOWED_HOSTS`, `DJANGO_CSRF_TRUSTED_ORIGINS`, секрет Django и пароль PostgreSQL. Для пароля БД используйте случайную hex-строку. Секреты можно создать через `python -c "import secrets; print(secrets.token_hex(32))"` — отдельно для каждого значения.
2. Направьте DNS A-записи домена и `www` на сервер и откройте порты 80/443. AAAA добавляйте только при настроенном IPv6. Порты базы и Gunicorn наружу не публикуются.
3. Выполните:

```sh
docker compose --env-file .env.production build
docker compose --env-file .env.production up -d db
docker compose --env-file .env.production run --rm web python manage.py migrate --noinput
docker compose --env-file .env.production run --rm web python manage.py seed_portfolio
docker compose --env-file .env.production run --rm web python manage.py createsuperuser
docker compose --env-file .env.production run --rm web python manage.py check --deploy
docker compose --env-file .env.production up -d
```

Caddy получит HTTPS-сертификат после настройки DNS. Загружайте изображения через админку после размещения; локальные данные и `user_design/` в Docker-образ не входят. Для обновления используйте `build`, миграции отдельной командой и `up -d`. Резервируйте PostgreSQL и том `media_data`; не удаляйте тома при обновлении.

## Границы готовности

Реализация основана на PDF. Figma API вернул лимит тарифного плана, браузер потребовал авторизацию, поэтому извлечение точных контуров и оригинальных изображений из Figma не выполнялось. Попиксельное совпадение с макетом не заявляется. Раздел «Обо мне» обновлён по скриншоту и предоставленным `Photo.png` / `Bg photo.svg`: имя и фамилия стоят в одной строке, под ними — утверждённая биография.

Для финального наполнения остаётся ссылка LinkedIn. Обложки проектов и PDF резюме подключены. При переносе сайта сохраняйте базу данных и каталог `media/` с загруженными файлами.
